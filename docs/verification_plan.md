# Verification Plan

## Verification policy

No simulation, synthesis, timing, power, or resource-utilization result should be claimed unless the corresponding command has been run and the output/report is available.

Current status:

- Python reference smoke checks: verified in the current environment.
- RTL simulation: MAC, dot-product, QK matmul, softmax approximation, and attention-top smoke simulations are verified in the current environment; later blocks and broader tolerance testing still need verification.
- Vivado synthesis: Needs verification.

## Milestone checks

### Skeleton and reference model

Planned/available checks:

1. Run the Python reference model self-test.
2. Generate deterministic vectors.
3. Confirm vector files use the expected dimensions and row-major order.

Acceptance criteria:

- Reference model runs without Python exceptions.
- Generated `Q`, `K`, and `V` files contain `SEQ_LEN * D_MODEL` signed integer values.
- Generated golden output contains `SEQ_LEN * D_MODEL` floating-point values.

### MAC unit and dot product

Implemented checks in this PR:

1. `tb_mac_unit` tests signed multiply-accumulate cases with positive, negative, and accumulated inputs.
2. `tb_dot_product` tests 8-element signed int8 dot products with vectors that are easy to verify by hand.
3. The dot-product tests include mixed signs and all-negative vector cases.

Acceptance criteria:

- `mac_unit` computes `acc_out = acc_in + a*b` with signed `DATA_W=8` operands and signed `ACC_W=32` accumulation.
- `dot_product` computes `sum(q[i] * k[i])` for `D_MODEL=8` using signed int8 vector lanes and signed int32 output.

Status: Verified by Icarus Verilog simulation when the commands listed in the PR/testing notes pass.

### QK matmul

Implemented checks in this PR:

1. `tb_qk_matmul` reads `vectors/q_input.mem` and `vectors/k_input.mem` when present.
2. The testbench compares the 8x8 signed int32 score matrix against `vectors/golden_score.mem` generated by Python when present.
3. The testbench falls back to internally computed expected scores if the golden score file is missing, keeping the unit test runnable for simple local experiments.
4. The RTL exposes a simple `IDLE -> RUN -> DONE` FSM and computes the unscaled `Score = Q*K^T` matrix only.

Acceptance criteria:

- Input `Q` and `K` are packed 8x8 signed int8 matrices.
- Output `Score` is a packed 8x8 signed int32 matrix in row-major order.
- Simulation completes with `done` asserted and every score matching the Python golden score file for the default vector set.

Status: Verified by Icarus Verilog simulation when the commands listed in the PR/testing notes pass.

### Softmax approximation

Implemented checks in this PR:

1. `tb_softmax_approx` checks row maximum extraction through the integrated softmax block.
2. The testbench checks a uniform row, a dominant-score row, and a mixed row with simple ordering and symmetry expectations.
3. The testbench checks that the Q0.8 probability sum is reasonable after integer truncation.

Acceptance criteria:

- Input is one packed row of eight signed int32 scores.
- `row_max` returns the signed int32 maximum score.
- `exp_lut` returns approximate unsigned Q8.8 exponentials of `score - max`.
- `row_sum` accumulates the eight approximate exponentials.
- `softmax_approx` emits eight unsigned Q0.8 probabilities.

Status: Verified by Icarus Verilog simulation for sanity properties only. This is not an exact floating-point softmax claim. Broader tolerance comparison against the Python model still needs verification.

### PV matmul and full attention

Implemented checks in this PR:

1. `attention_top` runs the first full pipeline: `LOAD_QKV -> QK_RUN -> SOFTMAX_RUN -> PV_RUN -> DONE`.
2. `tb_attention_top` reads generated `Q`, `K`, and `V` vectors and compares the 8x8 signed int32 output against `vectors/golden_output_fixed.mem`.
3. The golden fixed-point output is generated by the Python fixed-point reference that mirrors the current RTL softmax approximation.

Acceptance criteria:

- `done` and `valid` assert before the testbench timeout.
- Every output element is within the documented fixed-point tolerance for this smoke test.
- No AXI, DDR, or external memory interface is required for this milestone.

Status: Verified by Icarus Verilog smoke simulation for one generated vector set. Broader randomized tolerance testing against a higher-precision Python model still needs verification.
